# Make draft replacement resumable, inspectable, and explicitly confirmed

wxcli may replace one indexed article in an existing unpublished Draft Message only through a two-phase Draft Update Plan. Planning is read-only: it prepares the Word document, saves an exact Draft Snapshot backup, and reports a Draft Difference. Applying requires an explicit `--confirm`, verifies the prepared files have not changed, re-fetches the remote draft, and refuses the update when its fingerprint differs from the plan. After creation or replacement, wxcli reads the draft back and verifies its title, normalized body text, and body-image order. Providers remain read-only; these writes belong to the separate draft writer.

Image uploads use a non-secret Upload Checkpoint keyed by the prepared package and SHA-256 image hashes. The checkpoint is written atomically after each successful upload, allowing interruption recovery and deduplicating identical body images. It stores no AppSecret, access token, Cookie, or request authorization data. The trade-off is local state and an extra read request, accepted to reduce duplicate uploads and prevent blind or stale edits. Publishing, mass sending, deleting, editing without a plan, and bypassing verification remain forbidden.
