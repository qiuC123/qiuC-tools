# Support native Exa Direct Discovery without weakening evidence boundaries

Status: accepted

WeChat OA supports both Brave and Exa as replaceable Direct Discovery Providers because callers such as `official-campus-radar` invoke the CLI directly and may own only an Exa credential. The selected provider's key remains in the WeChat OA Windows credential store, never in process arguments, environment handoff, Candidate Batch data, or output; Brave remains the default for backward compatibility.

Exa receives one bounded `deep` search with the host-only domain filter `mp.weixin.qq.com`. A structured natural-language main query leads with de-duplicated company and account hints, describes them as Official Account preferences, includes small lexical variants for common campus-recruiting shorthand, and expresses the publication window as soft retrieval guidance. Bounded `additionalQueries` cover the caller wording, shorthand expansions, recruiting-program wording, and publication year. A fixed system prompt asks Exa to prioritize direct source articles and deprioritize other organizations, aggregators, reposts, interview stories, and generic roundups. The hints are not quoted as mandatory phrases, and publication windows are deliberately not sent as Exa `startPublishedDate` or `endPublishedDate` filters because those fields exclude indexed links whose provider metadata lacks a publication date. The window remains a ranking hint and, after Hydration, a filter over the WeChat-observed source date. Every returned URL must still pass WeChat OA's strict HTTPS `mp.weixin.qq.com/s` validation before it becomes an Article Candidate.

WeChat OA ranks the complete bounded provider page before applying the public candidate limit. An exact or related expected-account hint is preferred, an explicit different-account hint is demoted rather than rejected, and company/query/date metadata remains untrusted ranking input. The original Exa rank is retained in Search Provenance even when the candidate order changes. This avoids spending the bounded Hydration budget on obvious third-party noise without promoting any hint to Account Identity Evidence.

The Exa retrieval-strategy version participates in the private query fingerprint. Changing search planning invalidates only Exa's cached pages and opaque continuation tokens; it does not clear user data, change Brave fingerprints, or expose the strategy version in the public result schema. This prevents a newly installed retrieval strategy from silently reusing the prior version's successful but incomplete cached candidate page.

Exa titles, authors, dates, ranks, and identifiers remain untrusted search provenance. Only Hydration from the WeChat source may produce `published_at`, Account Identity Evidence, or Article Evidence, and selecting Exa never authorizes Chrome or Media Analysis.

The Direct Discovery result stays at schema v1 and the outer JSON envelope is unchanged. Existing top-level error codes and exit codes remain compatible; `error.details.provider` and the stable `error.details.reason` distinguish provider configuration, authentication, rate-limit, timeout, network, upstream-error, and invalid-response outcomes.
